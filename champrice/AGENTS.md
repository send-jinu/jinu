# Codex 작업 지침 — 들썩 참가격 API

## 목적
한국소비자원 `생필품 가격 정보_GW` API로 공산품 상품정보·가격을 조회하고, 들썩 식재료 원가계산기와 연결합니다.

## 저장소 현황
- `kamis_test.py`, `.github/workflows/kamis-test.yml`: 기존 KAMIS 수집. 변경·삭제하지 마세요.
- `champrice/verify_api.py`: 실제 참가격 상품목록·상품별 가격 응답을 확인하는 스모크 테스트.
- `.github/workflows/champrice-api-check.yml`: GitHub Actions 수동 실행 테스트.

## 필수 지침
1. 인증키는 GitHub Secret `CHAMPRICE_SERVICE_KEY` 또는 로컬 환경변수에서만 읽습니다. 공개 코드, HTML, 브라우저 JS, 로그에 넣지 않습니다.
2. 상품 조회 경로: `https://apis.data.go.kr/B551919/ProductPriceInfoService/getProductInfoSvc.do`. 문서상 `goodId` 생략 시 전체 조회.
3. 가격 조회 경로: 같은 기본 경로의 `getProductPriceInfoSvc`. `goodId` 또는 `entpId`가 필요합니다. 실제 호출 결과로 엔드포인트·응답 필드명을 확인합니다.
4. 상품명, 제조사, 규격, 상품 ID, 판매가격, 판매점, 조사일을 검증 가능한 형태로 연결합니다. 값이 없으면 **미확인**으로 남깁니다.
5. 골뱅이 통조림 등은 총내용량과 고형량을 구분합니다. 확인되지 않은 고형량을 임의 추정하지 않습니다.
6. 가격은 참가격의 조사 판매가격입니다. 현재 구매가능 가격이나 업소용 납품가로 오인시키지 않습니다.
7. 레시피 기준: 김밥 1줄(김 1장), 나머지는 1인분. 단위 변경 시 수치도 함께 환산합니다.
8. 실서버 테스트와 모의 응답 테스트를 구분하고, 확인되지 않은 공산품 가격을 만들어 넣지 않습니다.

## Codex 작업 순서
1. Actions `Champrice GW Live API Check`의 실제 실행 결과와 artifact를 확인하고 XML 구조·조회 범위를 파악합니다.
2. 상품 목록과 가격 데이터를 정규화하고, 필요한 경우 페이지 처리 및 오류·누락 처리를 구현합니다.
3. 사용자가 제공한 들썩 HTML 원가계산기에서 공산품 검색 → 상품 선택 → 규격·고형량 확인 → 단위당 원가 적용을 구현합니다.
4. 기존 KAMIS 농수산물 데이터와 참가격 공산품 데이터를 출처별로 병합합니다.
5. 자동 갱신, 단위 환산, 오류 처리, 보안, 테스트를 완료하고 실행법을 문서화합니다.

기존 원가계산기 HTML 파일은 사용자에게서 별도로 전달받아 작업하세요. 현재 공개 저장소에는 사용자 원본 HTML을 허락 없이 업로드하지 않습니다.
